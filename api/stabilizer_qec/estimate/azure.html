stabilizer_qec.estimate.azure

Azure's Resource Estimator: from logical counts (qubits, T, rotations, CCZ, measurements) to physical qubits and runtime on a chosen qubit model and QEC scheme, with the T factories found by the QDK's exhaustive search over distillation rounds and code distances, and the QDK's report: the counts formatted as it formats them and its groups of labelled, explained entries.

Two differences from the QDK are accepted. The QDK's counts are u64 and wrap silently when a product overflows (a runtime past 1.8e19 ns, a count past 2^64), where the integers here keep growing. And a float reaches the QDK through its JSON round trip, which keeps 15 significant digits exactly, so an input written with 16 or 17 may land one ulp away from the value used here.

>>> from stabilizer_qec.estimate import LogicalCounts, azure_estimate
>>> r = azure_estimate(LogicalCounts(num_qubits=100, t_count=100_000, ccz_count=10_000, measurement_count=10_000))
>>> r["physicalCounts"]["physicalQubits"], r["physicalCounts"]["runtime"], r["logicalQubit"]["codeDistance"]
(400060, 1064000000, 19)
>>> r["tfactory"]["numUnitsPerRound"], r["tfactory"]["codeDistancePerRound"]
([18, 1], [5, 15])
>>> r["physicalCountsFormatted"]["runtime"], r["physicalCountsFormatted"]["physicalQubits"]
('1 secs', '400.06k')
>>> res = LogicalCounts(num_qubits=100, t_count=100_000).estimate({"qubitParams": {"name": "qubit_gate_ns_e4"}})
>>> res["reportData"]["groups"][0]["title"], res.summary.splitlines()[1].split()
('Physical resource estimates', ['Runtime', '360', 'millisecs', 'Total', 'runtime'])

def evaluate_expression(expression: str, context: Dict[str, float]) -> float:

A QEC scheme's or distillation unit's formula evaluated as the QDK's fasteval evaluates it. The grammar is fasteval 0.2.4's: + - * / % ^, each its own precedence level from lowest to highest and ^ right-associative (so 7 * 3 % 2 is 7 and 2^3^2 is 512); unary minus binds tighter than every binary operator (-2^2 is 4, -(codeDistance^2) at distance 3 is −9); comparisons, and/&&, or/||, !; the functions min, max, abs, log, int, ceil, floor, round, sign, the trigonometric and hyperbolic ones, pi(), e(); inf and NaN. Constants fold at compile time as fasteval folds them (every constant of a +/* chain is combined first, so codeDistance + 0.1 + 0.2 is 3.3 and a NaN constant vanishes). Division by zero is infinite, a negative base to a fractional power NaN. Formulas over 4096 bytes or nested over 32 deep are refused, as are Python's own spellings (**, 1_000, 0x10). A formula that does not parse, or names a variable the context lacks, raises the QDK's EstimatorError CannotEvaluateExpression with fasteval's error (cannot evaluate expression: 'EofWhileParsing("value")', 'Undefined("d")').

def parse_time(value: Union[int, float, str]) -> int:

A duration in nanoseconds: a string such as "100 ns", "1 µs", "2 ms", "1 s" (the QDK's form, no surrounding spaces, the value rounded and saturated to u64 as the QDK's), or, beyond the QDK, a number of nanoseconds. Anything else is refused with serde's reason (invalid value: string "fast", expected cannot parse time).

The QDK's physical resource estimate from logical counts, as its EstimatorResult: status, jobParams, physicalCounts (physicalQubits, runtime in ns, rqops, a breakdown), physicalCountsFormatted (the same as the report's strings), logicalQubit, tfactory, errorBudget, logicalCounts and reportData (the report's groups of labelled, explained entries); with estimate_type="frontier", frontierEntries (each with those sections) along the qubits–runtime Pareto frontier instead, and the report of the first, whose sections the result's keys reach (result["physicalCounts"] is the first entry's).
