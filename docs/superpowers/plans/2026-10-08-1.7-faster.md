# 1.7 "Faster than the references" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. (This plan is executed inline, without subagents.)

**Goal:** Every benchmark ratio at or below 1.0 against Stim and PyMatching, on Apple silicon and on Linux x86_64, with every result unchanged bit for bit.

**Architecture:** Fingerprints of every output come first (Task 1), so no optimisation can change a result silently. Speed is measured natively on all three machine kinds: Apple silicon locally, and Linux x86_64 and Linux arm64 on GitHub's runners. Each hot path (error-model walk, graph-like search, matcher, frame sampler, m2d) is profiled with a native Rust harness and fixed where the profile points. A fix lands only with before/after ratios and green fingerprints.

**Tech Stack:** Rust engine (release profile, `--target aarch64-apple-darwin` locally: the host toolchain is x86_64 and runs under Rosetta), `samply` for profiles on macOS and `perf` on Linux runners, Stim 1.16 / PyMatching 2.4 as the timed references.

## Global Constraints

- Results never change: model text identical, shots identical for a seed (any thread count, any block width), decodes bit-identical. The gates are `tests/test_fingerprints.py` (Task 1) and `tools/matcher_bench.py --check`. **Run both before every commit.**
- Never run `cargo fmt`; match the long-line style. `cargo clippy --release --all-targets` and `--no-default-features` clean.
- Rust API: no change (`cargo semver-checks --baseline-version 1.6.0` passes). MSRV 1.87, so no `std::simd`. Portable code only, and no `unsafe` unless a profile proves it pays and a test covers it.
- Ratios come from `tools/bench.py`: the fastest of N repeats, one thread, against the reference in the same process. Local runs use the scratchpad venv. If another job is loading the machine, record the median of three runs and say so in the run's `note`.
- Commit per task on `feature/1.7`, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage with `git add -A -- . ':!.claude/launch.json'`, and check `git ls-files | grep ' [0-9]'` is empty (iCloud copies).
- Dev loop: `bash $SCRATCH/dev.sh` (arm64 wheel into `$SCRATCH/venv`); `$SCRATCH/venv/bin/python -m pytest tests -q`; `cargo test --release --no-default-features`.

### Task 1: Fingerprints of every result

**Files:**
- Create: `tests/test_fingerprints.py`, `tools/fingerprints.py`, `data/fingerprints.json`

**Interfaces:**
- Produces: `python tools/fingerprints.py` writes `data/fingerprints.json`, a map from case name to the sha256 of an output's bytes; `--check` recomputes it and exits 1 on any difference. `tests/test_fingerprints.py` runs the check in-process.

The cases, each on Stim's d = 5 rotated memory and on the gross code's memory (2 cycles):
- the error model's text: undecomposed, decomposed, folded, with `approximate_disjoint_errors`;
- detection events and observables from `compile_detector_sampler(seed=s).sample(n)` for s ∈ {0, 1, 2⁶³ + 5}, n ∈ {1, 63, 64, 65, 1000, 4097}, `threads` ∈ {1, 3, 0};
- `compile_sampler(seed).sample(n)` (raw measurements), `DetectorErrorModel.compile_sampler(seed)` (detections, observables, errors);
- m2d of 1,000 Stim-sampled measurement rows (`separate_observables` both ways);
- `Matching`, correlated `Matching`, `BpOsd`, `UnionFind` and `BeliefMatching` predictions on 2,000 shots;
- `shortest_graphlike_error` and `search_for_undetectable_logical_errors` model text, on Stim's colour code (d = 5) as well.

- [ ] **Step 1:** Write `tools/fingerprints.py` (the case list above, `hashlib.sha256` of `np.ascontiguousarray(x).tobytes()` or of the text's UTF-8), with `--check`.
- [ ] **Step 2:** Run it twice and confirm the two files are identical (the cases are deterministic). Run `--check` under `threads=1` and `threads=0` separately to confirm thread independence.
- [ ] **Step 3:** `tests/test_fingerprints.py`: one test per case (parametrized on `data/fingerprints.json`'s keys), each recomputing its hash. Marked to run in CI on every platform: the fingerprints must be the same on Linux, macOS and Windows, which also checks that a seed gives the same shots everywhere.
- [ ] **Step 4:** Push the branch and confirm CI's three platforms pass the new test (a platform difference is a bug to fix before any optimisation).
- [ ] **Step 5:** Commit `test: fingerprints of every result, so speed work cannot change one`.

### Task 3: The error model on Apple silicon (2.0× → ≤ 1)

**Files:** `src/dem_build.rs` (the backward walk), possibly `src/dem_program.rs` (text output)

- [ ] **Step 1:** Profile `hot dem` natively on arm64; record the top ten frames with their shares in the commit message.
- [ ] **Step 2:** Leads to test, in order:
  1. If text formatting (`fmt_g`, `format!`) is a large share: write numbers into one reused `String` buffer.
  2. Sensitivity sets: sorted `Vec<u32>` XOR-merges allocate on every gate. Reuse scratch vectors (`mem::take` and swap), and make two-qubit gates update in place.
  3. Class merging through `BTreeMap<Vec<u64>, …>`: a `HashMap` keyed by the symptom (FxHash-style hasher written in-crate, no new dependency), sorting once at the end so the output order is unchanged.
  4. Loop folding: compare periods by hash before comparing whole states.
  After each, rerun `hot dem` and the fingerprints.
- [ ] **Step 3:** Gate: Darwin ratio ≤ 1.0 by `tools/bench.py --only error_model --repeats 9`; Linux ratios not worse (`bench.yml`); fingerprints and `tests/test_stim_text.py` green.
- [ ] **Step 4:** Commit `perf: the error model at or below Stim's time on Apple silicon` with the before/after ratios on all three kinds.

### Task 6: Wider sampling, and m2d (m2d 1.26× on Apple silicon → ≤ 1)

**Files:** `src/batch_sampler.rs`, `src/m2d.rs`, `tests/test_threads.py`

Each 64-shot word keeps its own RNG stream (`batch_seed(seed, b)`), so the shots for a seed cannot change. A block now processes W words side by side, as a `[u64; W]` the compiler vectorises (W = 4: 256 shots).

- [ ] **Step 1:** Profile `hot m2d` and `hot sample` on arm64; record the frames.
- [ ] **Step 2:** m2d first, since it is over target: leads are transposing the measurement rows into words with a byte-wise 8×8 transpose instead of bit by bit, and XOR-accumulating detectors over words in one pass.
- [ ] **Step 3:** The sampler: generalise `State` to `[u64; W]` lanes behind a const generic. Gates operate lane-wise; noise draws for word `k` come from word `k`'s stream exactly as now. Choose W by measurement (1, 2, 4, 8) on all three kinds.
- [ ] **Step 4:** Extend `tests/test_threads.py`: the same shots for a seed across thread counts and across W (W is exposed only to tests, through `_core`).
- [ ] **Step 5:** Gate: m2d ≤ 1.0 on Darwin; sample not worse anywhere; fingerprints green.
- [ ] **Step 6:** Commit `perf: m2d below Stim's time everywhere, sampling in blocks of W words`.
