# 2.0 W10: fault-tolerant compilation and estimation — implementation plan

**Goal:** the spec's W10 (inventory F1–F8, M5, M10): tqec's block graphs, gallery and Collada
files; Loom's code operations, validator and exporters; estimator parity with Qualtran's
surface-code models and Azure's Resource Estimator; each checked against its reference.

**Where things stand.**
- M5 (code switching) and M10 (lattice-surgery routing) are done (W6:
  `stabilizer_qec.mqt_qecc.code_switching`, `stabilizer_qec.mqt_qecc.cococo`).
- Lattice surgery exists in Rust (`src/surgery.rs`: merge/split programs, the logical CNOT,
  repeated merges, lines) with Python `stabilizer_qec.surgery`; the resource estimator lives
  in the site (`js/estimator.js`, `tools/estimate.mjs`): Λ-driven footprints, factories
  (cultivation, Litinski), data blocks, reaction time, storage.
- F1–F8 are parts or gaps: no block-graph model, no Collada, no Loom-style code operations or
  validator, no exporters, no Qualtran/Azure cost models.

**References** (Apache 2.0 all; wheels and sdists in the scratchpad, installed in the test venv
for the differential tests).
- tqec 0.2.0: `BlockGraph` (cubes, pipes, ports; ZX kinds; validation; `fill_ports`;
  `compose`; `rotate`; correlation surfaces through ZX), the gallery (memory, stability, CNOT,
  CZ, move/rotation, three CNOTs, Steane encoding), `.dae` (pycollada) and JSON IO,
  `compile_block_graph` (templates, plaquettes, detector search with a SAT solver), sinter
  simulation helpers.
- el-loom 0.4.0 (Entropica's Loom): `Eka` (lattice, blocks, stabilizers), code operations
  (Grow, Shrink, Merge, Split, StateInjection, logical measurements and Paulis, conditional
  Paulis; the rotated-surface-code factory with move, rotate, corner moves, Y-wall,
  transversal H, auxiliary CNOT in its applicators), the interpreter (operations → circuits,
  detectors, observables), the validator (stabilizer, logical-operator and
  syndrome-measurement checks on a Clifford simulator), exporters (Stim, QASM 3, PennyLane,
  CUDA-Q, Mimiq, Guppy). Depends on pydantic, igraph, plotly, scipy: none of them ported.
- Qualtran 0.7.0 `qualtran.surface_code`: `QECScheme` (Gidney–Fowler, Beverland), logical
  error models, `PhysicalCostModel`, data blocks (simple, compact, intermediate, fast),
  factories (CCZ2T levels, 15-to-1, multi-factory), rotation cost models, `AlgorithmSummary`,
  physical parameters, the Gidney–Fowler grid search; its tests pin the numbers.
- The QDK's resource estimator (`qdk[qre]`, runs locally): Azure RE's qubit parameters
  (gate-based and Majorana, separate readout and idle errors), surface and Floquet schemes
  with their formulas, distillation units, error-budget split, constraints, the Pareto
  frontier; its JSON reports are the check.

**Architecture.** Python modules in the package's idiom, Rust where there is simulation:
- `stabilizer_qec.tqec`: tqec's `computation` package ported (block graphs, cubes, pipes,
  ports, ZX graph, correlation surfaces), its gallery, and its JSON and Collada IO written
  with the standard library (Collada is XML; the geometry is boxes), without pycollada.
  Compilation to circuits goes through this package's surgery engine for the graphs it can
  express (time pipes as memory rounds, spatial pipes as merges and splits, cube kinds as
  boundary bases and the initial and final bases), which covers memory, stability, CNOT and
  three CNOTs; CZ (Hadamard pipes), move/rotation and Steane encoding compile through tqec
  itself where it is installed and are documented as such.
- `stabilizer_qec.loom`: Loom's `eka` model (lattice, block, stabilizer, operations), the
  rotated-surface-code factory and its applicators, the interpreter to this package's
  `Circuit`, the validator on this package's `TableauSimulator`, and the exporters, with
  dataclasses for pydantic, this package's graphs for igraph, and no plotting.
- `stabilizer_qec.estimate`: Qualtran's models ported one to one (dataclasses for attrs,
  floats for sympy), and an Azure RE model (`AzureEstimator`) reproducing the QDK's formulas
  for the surface and Floquet schemes, qubit parameter sets, distillation units, the budget
  split, constraints and the frontier.

## Tasks

1. **Block graphs** (F1, F3, and the gallery's data, F2).
   - `stabilizer_qec.tqec`: `BlockGraph`, `Cube`, `Pipe`, `Position3D`, kinds (`ZXCube`,
     `YHalfCube`, `Port`, pipe kinds with Hadamard), `validate`, `fill_ports`,
     `fill_ports_for_minimal_simulation`, `compose`, `shift_by`, `rotate`,
     `fix_shadowed_faces`, `to_zx_graph` and `find_correlation_surfaces` (the ZX graph and the
     correlation-surface search, pyzx-free), `to_json`/`from_json`, `to_dae_file`/
     `from_dae_file` (Collada XML with tqec's node names, scales and colours), the HTML viewer
     left out. The gallery's seven builders.
   - Checks: Loom-free; against tqec installed: every gallery graph's cubes, pipes, ports,
     spacetime volume and correlation surfaces equal tqec's; JSON and dae round-trip through
     tqec (`tqec.BlockGraph.from_dae_file` reads ours, we read tqec's gallery dae files).
2. **Compiling block graphs** (F1, F2).
   - `BlockGraph.compile(distance, rounds)` → `Circuit`: the graph's cubes and pipes read as
     a schedule of patch operations on this package's surgery engine (memory, merges, splits,
     boundary bases, initializations and measurements in the port bases), the correlation
     surfaces as observables, detectors from the engine; a graph with a Hadamard pipe, a
     spatial junction of two directions or a Y cube is refused with tqec named.
   - Checks: against tqec installed: for memory, stability, CNOT (both bases) and three CNOTs
     at d = 3 and 5, the compiled circuits' detector counts, observable counts, graph-like
     distances (`shortest_graphlike_error`) and sampled logical error rates under uniform
     depolarizing noise agree (the circuits differ in schedule; the distances must not).
     tqec's gallery circuits run through this package's DEM builder and decoders.
3. **Loom** (F4, F5).
   - `stabilizer_qec.loom`: `Eka`, `Lattice`, `Block`, `Stabilizer`, `PauliOperator`, the
     operations (code and logical), `RotatedSurfaceCode` with its applicators (grow, shrink,
     merge, split, move, rotate, move corners, Y-wall, state injection, transversal Hadamard,
     auxiliary CNOT, logical measurements), `interpret_eka` → `Circuit` with detectors and
     observables, `is_circuit_valid`, `is_syndrome_extraction_circuit_valid`,
     `is_logical_operation_circuit_valid` on `TableauSimulator`, and exporters to Stim (this
     package's text), OpenQASM 3, PennyLane and CUDA-Q (Mimiq and Guppy left out, with a note).
   - Checks: Loom's own unit tests ported where they do not need pydantic or plotting; against
     Loom installed: each applicator's circuit equals Loom's (same stabilizers, same detectors,
     same observables, Stim text equal after the circuit's canonical form), the validator's
     verdicts equal on Loom's valid and invalid examples, the exporters' text equals Loom's.
4. **Estimator parity** (F6, F7).
   - `stabilizer_qec.estimate`: Qualtran's `surface_code` ported (`QECScheme`,
     `LogicalErrorModel`, `PhysicalParameters`, `PhysicalCostModel`, the data blocks, the
     factories, `MultiFactory`, the rotation cost models, `AlgorithmSummary`, `GateCounts`,
     `get_ccz2t_costs`, `get_ccz2t_costs_from_error_budget`, `get_ccz2t_costs_from_grid_search`,
     Beverland's `minimum_time_steps`, `code_distance`, `n_discrete_logical_gates`,
     `t_states`); and `AzureEstimator` with the QDK's `qubit_gate_ns_e3`/`e4`,
     `qubit_gate_us_e3`/`e4`, `qubit_maj_ns_e4`/`e6` parameter sets, `surface_code` and
     `floquet_code` schemes (their error-rate, time and space formulas), distillation units
     (15-to-1 RM prep, space- and time-efficient), the error budget split (logical, T states,
     rotations), constraints (max T factories, max duration, max physical qubits) and the
     frontier.
   - Checks: Qualtran's tests' values; against the QDK's local estimator on its documented
     examples (the Q# samples' operation counts): physical qubits, runtime, code distance,
     T-factory counts equal (to the rounding the report prints).
5. **Plaquette's leakage thresholds** (F8): `tools/surgery_leakage.py` runs the lattice-surgery
   CNOT (`stabilizer_qec.surgery.cnot`) under the leakage sampler's model at several leakage
   rates and finds the threshold, as Plaquette's study does; a short README table.
6. **Bookkeeping.** CHANGELOG, inventory (F1–F8), THIRD_PARTY_NOTICES (tqec, Loom, Qualtran),
   README's feature list, API docs.

Each task: tests first where the reference makes that possible. One commit each, and push.
