# 2.0 W11: real time and GPU — implementation plan

**Goal:** the spec's W11 (inventory C6, C7, C10, T8): CUDA-Q QEC's asynchronous and streaming
decoder API with decoder statistics, a decoder server over TCP or stdin/stdout, and frame
sampling and BP on the GPU through `wgpu` as an optional feature, checked bit for bit against
the CPU.

**Where things stand.**
- Real time exists as `stream_memory` (Rust `src/stream.rs`, `src/window.rs`): a million-round
  memory sampled and window-decoded as it streams, 64 streams per detection word, on a thread
  pool (`src/parallel.rs`). Every DEM decoder has `decode` and `decode_batch` (`_DemDecoder`,
  `python/stabilizer_qec/_decoders.py`), each batch released from the GIL and cut across
  threads in Rust (`src/batch.rs`).
- `stabilizer_qec.cudaq_qec` (W6) has CUDA-Q QEC's `Decoder` with `decode`, `decode_batch`
  and a `decode_async` that runs the decode eagerly and hands back an `AsyncDecoderResult`
  (`ready()`, `get()`); nothing is queued or timed, and there is no `enqueue_syndromes`/
  `get_corrections`/`reset_decoder`, no latency statistics, no server.
- Sampling is `BatchSampler` (`src/batch_sampler.rs`): 64 shots per machine word, the X and
  Z frames two words per qubit, noise words drawn by geometric skipping from a per-batch
  `Xorshift` (`batch_seed(seed, b)`, SplitMix64), `f64` logs in the skip. Python's
  `compile_detector_sampler().sample(shots, threads)` reserves batches and runs them across
  threads (`PySampler`, `src/py_objects.rs`). BP is `src/bp.rs` (product-sum and min-sum,
  parallel and serial schedules, f64), run per shot across threads (`bposd_shots`).
- No GPU anywhere; the crate's features are `python` and `highs` only.

**References.**
- CUDA-Q QEC 0.8's decoder interface (`cudaq_qec.Decoder`: `decode`, `decode_async` →
  `async_decoder_result.ready()/get()`, `decode_batch`, `decode_multi`, `get_block_size`,
  `get_syndrome_size`, `get_version`) and its real-time host API (`enqueue_syndromes(decoder,
  syndromes)`, `get_corrections(decoder)`, `reset_decoder(decoder)`, `configure_decoders`), where
  the syndromes of a running kernel are queued to a decoder and the corrections read back when
  needed; its decoder statistics (per-call latency). The package is not installed here (the
  scratch venv of reference packages was purged with /tmp); the API is reproduced from its
  documentation and from the W6 port's shape.
- cuStabilizer (NVIDIA, 2026): GPU frame sampling with X/Z tables and leakage, quoted at up
  to 150× one CPU thread. No source; its published ratio is the comparison.
- `wgpu` (the Rust WebGPU implementation: Metal, Vulkan, DX12, OpenGL, and WebGPU on wasm) and
  WGSL, which has `u32`, `i32`, `f32`, no `u64` and no `f64`.

**Architecture.**
- `stabilizer_qec.realtime` (Python) over a Rust `src/realtime.rs`:
  - `AsyncResult` (`ready()`, `wait(timeout)`, `get()`), returned by a new `decode_async(shots)`
    on every `_DemDecoder`: the batch runs on a Rust worker thread, the GIL released, the result
    the same bytes `decode_batch` would give.
  - `DecoderQueue(decoder, *, workers=1)`: `enqueue_syndromes(shots) -> ticket`,
    `get_corrections(ticket=None, timeout=None)` (the next finished batch in order of enqueue,
    or that ticket's), `pending()`, `reset()` (drops queued work, clears the statistics),
    `stats()` → `DecoderStats(decoded, batches, mean_latency_s, p50, p99, max, throughput_per_s,
    queue_depth_max)`. Latency is enqueue to completion, wall clock, measured in Rust.
  - `cudaq_qec.Decoder.decode_async` keeps its shape and runs on the queue; `cudaq_qec` gains
    `enqueue_syndromes`, `get_corrections`, `reset_decoder` and `configure_decoders` as
    module-level functions over named decoders, as CUDA-Q QEC's host API spells them.
- `stabilizer_qec.realtime.serve` and `DecoderClient`:
  - A framed protocol, the same over TCP and over stdin/stdout: a 16-byte header (magic
    `SQRT`, version, message kind, payload length) and a payload; kinds `HELLO` (JSON: the
    model's detector and observable counts, the decoder's name), `DECODE` (b8 syndromes, the
    shot count in the header's tail) answered by `CORRECTIONS` (b8 predictions), `STATS` (JSON),
    `RESET`, `BYE`. One connection at a time per worker; the TCP server takes `--workers`.
  - CLI: `stabilizer-qec serve --dem model.dem --decoder matching [--tcp 127.0.0.1:7455 |
    --stdio] [--workers N] [--correlated]`, and `--circuit c.stim` with the decoder's model
    built here. `DecoderClient.connect(host, port)` / `DecoderClient.spawn(argv)` with
    `decode_batch`, `stats`, `reset`, `close`; a context manager.
- `src/gpu/` behind a Cargo feature `gpu = ["dep:wgpu", "dep:pollster"]` (and `maturin`'s
  Python feature `gpu` extra, `pip install stabilizer-qec[gpu]` installs the same wheel: the
  feature is compiled in when the wheel is built with it; the release wheels carry it, a device
  is found at run time or `device="gpu"` raises).
  - A lane sampler, the CPU reference: `BatchSampler::run_lanes32` draws every noise location
    per lane as `next_u32() < threshold` (threshold = round(p · 2³²), the lane's own xorshift32
    stream seeded from the batch seed and the lane), 32 shots per `u32` word, the composite
    channels choosing their Pauli from the next draw's high bits; integer only, so a GPU can
    repeat it bit for bit. Python: `compile_detector_sampler(..., device="cpu-lanes")`.
  - The WGSL sampler: the circuit's op program (the `Op` list `batch_sampler.rs` compiles,
    flattened into a `u32` instruction buffer: opcode, qubit, partner, record index, threshold,
    detector lookbacks), one invocation per 32-shot word, frames in storage buffers
    (`x[word][qubit]`, `z[word][qubit]`), measurement records in a ring per word, detectors
    written as made; REPEAT blocks iterated on the GPU; results read back as b8. Python:
    `device="gpu"`; `stabilizer_qec.gpu.devices()` lists adapters.
  - Min-sum BP in WGSL, f32, one invocation per shot over a shared check matrix in CSR/CSC
    buffers, the parallel schedule, `max_iter` fixed: `BpDecoder(..., device="gpu")`
    (min-sum only; product-sum's `tanh`/`atanh` are not bit-stable across GPUs). The CPU
    reference `src/bp.rs` gains an f32 min-sum path with the same operation order
    (`BpDecoder(..., device="cpu-f32")`); they must agree bit for bit.
  - `tools/gpu_bench.py` → `data/gpu/bench.json`: shots per second of the CPU sampler at 1 and
    all threads, the lane sampler, and the GPU, on d = 5, 11, 17 memories at 10⁶ shots; BP the
    same way on a [[144,12,12]] code; the ratios beside cuStabilizer's published 150×.
  - The site: WebGPU through the wasm build is W12's (the site's wasm build has no features
    yet; the kernel sources are shared, nothing in them is native-only).

## Tasks

1. **Asynchronous decoding and the queue** (C6).
   - `src/realtime.rs`: a worker pool owning a decoder (any `SyndromeDecoder`/matching/BP+OSD
     over the existing batch functions), a channel of jobs (b8 shots, ticket, enqueue time),
     results by ticket with their timings; `Stats` with the latency histogram.
   - Python `stabilizer_qec.realtime`: `AsyncResult`, `DecoderQueue`, `DecoderStats`;
     `_DemDecoder.decode_async`; `cudaq_qec`'s host functions over it.
   - Checks: `get_corrections` equals `decode_batch` shot for shot on every decoder class
     (matching, correlated, union-find, BP+OSD, BP+LSD, Relay-BP, local clustering, search);
     tickets come back in enqueue order; `reset` empties the queue; stats count what ran and
     their latencies are positive and bounded by the wall time; a GIL-released decode runs
     while Python counts.
2. **The decoder server** (C7).
   - `stabilizer_qec.realtime.protocol` (framing), `serve` (TCP with `socketserver`, stdio),
     `DecoderClient`; CLI `serve` in `_cli.py`.
   - Checks: a subprocess server over stdio and a thread server over TCP decode 10,000 d = 5
     shots equal to local decoding; stats match; a bad frame returns an error frame and keeps
     the connection; a `--circuit` server equals a `--dem` one of the same model.
3. **The lane sampler on the CPU** (the GPU's reference).
   - `BatchSampler::run_lanes32` and `sample_lanes_seeded`; `PySampler` with a `device`;
     `Circuit.compile_detector_sampler(device=...)` and `sample`; the same for
     `compile_measurement_sampler`.
   - Checks: its detector and observable rates equal the word sampler's within sampling error
     on the memory circuits and the leakage circuits (the model is identical, the streams are
     not); the same seed gives the same bytes on 1 and 8 threads and across calls; the per-lane
     frame semantics match `FrameSampler` on 150 random small circuits (a lane and a shot drawn
     with the same bits agree).
4. **The GPU sampler** (C10, T8).
   - Cargo feature `gpu`; `src/gpu/mod.rs` (device, buffers, dispatch), `src/gpu/sample.wgsl`,
     the op encoder; `stabilizer_qec.gpu.devices()`; `device="gpu"` in the samplers; CI
     builds the feature on every OS and the tests skip without an adapter.
   - Checks: bit-identical to `run_lanes32` for every seed and shot count on the memory, colour,
     BB and surgery circuits and on 150 random circuits (REPEAT, sweeps, feedback, heralds,
     composite channels, leakage); throughput recorded by `tools/gpu_bench.py`.
5. **BP on the GPU.**
   - f32 min-sum in `src/bp.rs` (CPU, the same operation order) and `src/gpu/bp.wgsl`;
     `BpDecoder(..., device=...)`, `BpOsdDecoder` with a GPU BP stage.
   - Checks: GPU equals CPU-f32 bit for bit on the [[144,12,12]] and d = 11 surface memories
     over 10⁵ shots; CPU-f32 min-sum against the f64 min-sum agrees on the decoding of 99.9% of
     shots and in its logical error rate within sampling error; throughput recorded.
6. **Bookkeeping.** README (a "Real time and GPU" section with the tables), CHANGELOG,
   inventory (C6, C7, C10, T8), THIRD_PARTY_NOTICES (wgpu's licence), `_core.pyi`, API docs,
   `pyproject.toml` extras, wheels workflow with the feature.

Each task: tests first where the reference makes that possible. One commit each, and push.
