# Real-Time Decoding Implementation Plan (C2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Decode a stream of syndrome rounds as they arrive: sliding-window and parallel-window decoders over any detector error model with time coordinates, plain and correlated; their accuracy against global decoding, on SD6 circuits and on Google's Willow data; their latency and throughput against Willow's 1.1 µs cycle; a million-round stream; and section 12 of the site.

**Architecture:** Plan C2 of sub-project C (spec: `docs/superpowers/specs/2026-09-26-real-time-design.md`, Part 2).
- `src/window.rs` cuts window graphs out of a model's merged edges, by layer (time coordinate). An edge leaving the window becomes a boundary half-edge of its own, so a defect can wait for a partner not yet seen.
- It decodes each window to an edge set with the sparse matcher (pass two's edges for correlated matching), commits the edges touching the commit region, and toggles their far ends into the next region.
- Parallel windows run in two layers. Layer B fills the gaps between layer A's commit regions.
- Latency comes from real per-window decode times scheduled in virtual time at a 1.1 µs cadence over K cores, and a real multithreaded run confirms the throughput.
- The million-round stream uses the batch sampler's stream mode, with window graphs built once from a short model (time translation).

**Tech Stack:** Rust 2021 (no new crates), PyO3 (`--profile python`), plain ES modules, the worker pool.

## Global Constraints

- The global decoder is unchanged, and it is the oracle: a window as large as the stream must reproduce its predictions exactly.
- Every decoded shot must leave no defect unexplained: the committed edges' syndrome equals the shot's defects. This is checked on every shot in tests, and counted in the tools.
- Latency numbers name the machine (Apple M2 Pro) and are built from measured decode times.
- Tests as in C1. Commit per task on `feature/real-time`.

## Definitions

- **Layer:** the index of a detector's time coordinate (the last one) among the model's distinct times, in order.
- **Window `[a, b)`:** the detectors with layers in `[a, b)`, with:
  - edges with both ends inside;
  - real boundary edges;
  - optionally a **future boundary** (each edge to a layer ≥ b becomes a boundary half-edge of its inside end) and a **past boundary** (likewise for layers < a).

  Edges to layers outside without those options are dropped.
- **Commit region `[c0, c1)`:** a window's committed edges are those with at least one end in it (a boundary edge's one end). Committing XORs the edge's observables into the prediction and toggles both its ends' defects, so a committed edge reaching past the commit region leaves a defect for the region it reaches.
- **Sliding (C, B):** windows `[kC, kC + C + B)` with a future boundary and commit region `[kC, kC + C)`. The last window runs to the end, commits everything and has no future boundary.
- **Parallel (C, B):**
  - Layer A: windows `[s − B, s + C + B)` (clipped to the stream), with a past boundary unless they start at layer 0 and a future boundary unless they end at the last layer, and commit region `[s, s + C)`. Here s = 0, C + 2B, 2(C + 2B), ….
  - Layer B: the gaps between consecutive A commit regions, and the tail after the last one, each a window with no virtual boundaries, committing everything.
  - A windows are independent of each other, and so are B windows.

### Task 2: Committing, sliding and parallel

**Files:** `src/window.rs`.

**Interfaces:**

**Tests:**
- **Exactness in the limit.** With C ≥ the number of layers, sliding and parallel predictions equal global decoding's on every shot of SD6 rotated and XZZX at d = 3 and 5 (T = d), plain and correlated.
- **Bookkeeping.** `unexplained == 0` on every shot, for C = 1…3 and B = 0…3, both modes, both matchers, on SD6 d = 3 and 5 at T = 10.
- **Accuracy in miniature.** Rotated SD6 at d = 5, T = 30, p = 0.5%, 3,000 shots. With C = B = d, sliding and parallel failures are within 4σ of global's, σ being the square root of the number of shots on which they differ.

### Task 4: Latency and throughput

**Files:** `tools/realtime.py` (`latency`), `src/py_api.rs` (`stream_decode_threads`: a real K-thread decode of one stream's windows, returning the wall time).
- **Virtual-time schedule.** Inputs: the measured window times, the windows' last layers, τ = 1.1 µs, and K.
  - Sliding: window k is released when its last layer arrives, and each runs after the one before it on one worker. Sliding cannot use more than one core per stream, since each window needs the last one's toggles.
  - Parallel: A windows are released when their last layer arrives, and B windows when both their neighbouring A windows are done and their own last layer has arrived. Each goes to the earliest free of K workers.
  - Latency per window: completion minus the arrival of its last layer. Report the mean and the 99th percentile, and "keeps up" (the latency does not grow along the stream: the last quarter's mean is within 10% of the second quarter's).
- **Streams:**
  - Willow's d = 3, 5, 7 at 250 rounds (every shot, SI1000 prior, plain and correlated);
  - SD6 at d = 3, 5, 7 over 250 rounds, with p chosen so the detection fraction is Willow's (measured from the Willow records);
  - K ∈ {1, 2, 4, 8}.
- **A real run.** Parallel windows of Willow d = 7 at 250 rounds on K real threads: the measured throughput in rounds per second against the schedule's.
- Results go to `data/realtime/latency.json` and a printed table.

### Task 5: A million rounds

**Files:** `src/batch_sampler.rs` (the sink receives each detector's time coordinate: `Op::Detector` keeps its last coordinate, and `SHIFT_COORDS` is kept as an op that moves a running offset), `src/window.rs` (`PeriodicWindows`), `src/py_api.rs` (`stream_million`), `tools/realtime.py` (`million`).
- `PeriodicWindows::new(short: &Model, commit, buffer)`: the first window, the bulk window and the last window, taken from a short model of the same code (T_short = 3(C + B) + 2).
  - **Test:** in a 60-round model, the bulk windows at three offsets are identical after shifting (nodes, edges, weights, observables).
- **The stream.** The batch sampler runs a `REPEAT 1000000` rotated SD6 d = 5 circuit, 64 streams at once. Detector words are buffered by layer. As each window's last layer completes, each lane's defects in it are decoded with the matching window graph, and committed, with toggles carried forward.
  - Memory is the window's layers, not the stream.
  - **Reported:** window decode-time percentiles; the latency and keep-up verdict from the schedule at K = 1…8; the wall time; and a check that every lane ends with no unexplained defect.
  - It checks against the sampler too: the shorter model's per-window graphs are re-derived for a 1,000-round stream, and the million-round decoder's bookkeeping holds.
