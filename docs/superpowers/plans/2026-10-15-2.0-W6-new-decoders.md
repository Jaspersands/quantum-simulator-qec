# 2.0 W6: new decoders — implementation plan

**Goal:** the decoders other tools have and we lack (spec W6: D1–D4, U8, U10, U11, C1–C3, C5,
Q14, M6, M7, X4, X5), each checked against its reference where one runs here, and otherwise
against brute force or its paper.

**Architecture.** Algorithms in Rust (new `src/lookup.rs`, `src/hyper_uf.rs`, `src/mwpf.rs`,
`src/partition.rs`, `src/cluster.rs`, `src/tn.rs`, `src/cnn.rs`), each a `_DemDecoder` in
`python/stabilizer_qec/_decoders.py` (shots in, observables out, pickled by its model and
options, a sinter name in the built-in decoder table). Where a reference has a Python package
(`mwpf`, `fusion_blossom`, `qecsim`) its API is ported as a drop-in subpackage, as W5 did.

**Check.** Differential tests against the installed references (`mwpf`, `fusion_blossom`,
`qecsim`), brute force for the exact decoders, and the published thresholds and curves for the
clustering decoders; the conformance suite (task 7) runs over every decoder we ship.

## Tasks

1. Exact and small decoders (Q14, C2, M6): **`stabilizer_qec.qldpc`, qLDPC 0.4.1 whole**
   (Apache-2.0, pure Python), its QEC stack (Stim, ldpc, PyMatching, sinter, relay_bp,
   Tesseract) pointed at this package and its own tests (23k lines) passing. Its decoders give
   Q14 entire: lookup (plain, weighted, observable), ILP, GUF, composite, direct, frontier,
   subgraph, sequential and sliding windows, trivial, erasure flags. It also brings most of W7's
   Q items (codes, distance, groups, encoders, memory experiments), which W7 then checks off.
   An extra (`stabilizer-qec[qldpc]`: galois, sympy, cvxpy, networkx, diskcache, platformdirs,
   pyperclip) and Python 3.11+, as qLDPC. Then CUDA-Q's single- and multi-error lookup tables
   (C2) and a MaxSAT colour-code decoder (M6) in Rust, against brute force.
2. Hypergraph decoders (D2): MWPF's hypergraph minimum-weight parity factor and hypergraph
   union-find, and `stabilizer_qec.mwpf` (its `SolverInitializer`, `SolverSerialJointSingleHair`,
   `SolverSerialUnionFind`, `SyndromePattern`, `HyperEdge`, sinter decoder); identical weights
   to `mwpf`.
3. Parallel matching by partitions (D3): Fusion Blossom's partitioned MWPM (partition by time,
   fuse along boundaries) and `stabilizer_qec.fusion_blossom` (`SolverInitializer`,
   `SolverSerial`, `SolverParallel`, `PartitionConfig`, `SyndromePattern`); identical weights.
4. Clustering decoders (C1–C3): Collision Clustering, the Local Clustering Decoder (adaptive,
   leakage-aware) and Ambiguity Clustering; against their papers' thresholds and curves.
5. Tensor-network ML decoding (M6, M7): exact contraction (small codes, against exhaustive ML)
   and MPS with a bond-dimension cut for planar, toric and colour codes; `stabilizer_qec.qecsim`
   decoders matching qecsim's on planar codes.
6. Wrappers (X4): analog (soft-syndrome) decoding, a sliding window around any inner decoder,
   composite and subgraph decoders.
7. Post-selection and checks (D1, D4, X5): post-selection by soft output (arXiv 2601.17757),
   leakage-aware decoding from heralds, and decoder conformance checks over every decoder.
8. The AI pre-decoder (C5): a 3D CNN in front of matching (NVIDIA's shape, arXiv 2604.12841);
   inference in Rust, training in numpy (and Rust), our own weights; measured by the logical
   error it saves over matching alone. CHANGELOG.

## Status

Task 1, first part: `stabilizer_qec.qldpc` ported whole (qLDPC's 953 tests pass on it, as on
qLDPC). Porting found five places this package differed from the references it stands in for
(anti-Hermitian `MPP`, Stim's non-determinism message, relay_bp's observable matrix and
signature defaults, ldpc's `random_serial_schedule` on BP+LSD), all fixed.

Task 1 also: CUDA-Q QEC's lookup tables (C2), and with them `stabilizer_qec.cudaq_qec` (its
decoder interface, its sliding window, C3 of task 6, and its tensor-network decoder, exact
contraction, C1 of task 5), passing CUDA-Q's decoder tests.

Task 5: `stabilizer_qec.qecsim`, qecsim 1.0b9 whole (its 2,902 tests pass), brings its MPS
tensor-network decoders (planar, rotated planar, colour 6.6.6; exact and by bond dimension), and
`stabilizer_qec.bposd` bposd 2.1.

Task 1 (M6) and task 6 (analog, M7): `stabilizer_qec.mqt_qecc`, MQT QECC 2.0.0 whole (its tests
pass as on MQT QECC, 938, and its five command-line tests MQT needs a plugin for): the MaxSAT
colour-code decoder (LightsOut, by Z3 or an external solver) and analog information decoding,
with its fault-tolerant state preparation and codes for W7. Porting it found that a circuit's
`pop` and slicing fused neighbouring instructions where Stim's leave them apart; circuits now
keep Stim's list of instructions exactly.

Task 3: `stabilizer_qec.fusion_blossom`, Fusion Blossom 0.2.13 ported whole to Rust
(`src/fusion/`, its 80 Rust tests passing, Blossom V's comparisons on this package's exact
matcher) under its Python module (`src/py_fusion.rs`): matchings, subgraphs, dual sums,
snapshots, example codes' random errors, visualizer files and JSON text equal to
fusion_blossom's, serial and partitioned (`tests/test_fusion_blossom_package.py`), and its
Python tests and scripts passing (`tests/fusion_blossom_port/`). sinter's `fusion_blossom`
decoder runs on it. Porting it found an upstream deadlock: with `max_tree_size`, a tree that
absorbed a matched pair collapsed with its root still locked (fusion_blossom's wheels use raw
pointers, so never lock).

Task 2: `stabilizer_qec.mwpf`, MWPF 0.2.12 ported whole to Rust (`src/mwpf/`, its 131 Rust tests
passing) under its Python package, its command line included (help, errors and seeded output as
MWPF's, `tests/test_mwpf_cli.py`). Subgraphs, weight bounds, snapshots, random errors, configs and
their errors, and sinter's predictions on circuits (BP pre-decoder included) equal MWPF's
(`tests/test_mwpf_package.py`); its Python tests pass (`tests/mwpf_port/`). Two findings changed
the plan below: MWPF is deterministic (in the wheels' build its iterated sets are BTrees, and its
hash maps are only looked up), and the optimum its LP solver picks among many steers its relaxers,
so a simplex of our own gave other subgraphs, and on some inputs ran thousands of times longer
(round-off ties made it cycle). HiGHS 1.8.0 is therefore vendored (`src/highs/`, compiled by
`build.rs` with HiGHS's Release flags for the `highs` feature, on in the wheels) and called as the
`highs` crate calls it; the simplex stays for Rust builds without it, with a perturbed ratio test
so that it cannot cycle. QEC-Playground's codes (MWPF's `qecp` feature) are not included.

Task 4, first part: Ambiguity Clustering (`src/ambiguity.rs`, `AmbiguityClustering`) from its
paper. No reference implementation is public (Riverlane's runs in its cloud), so the checks are
its paper's claims on our circuits: at kappa 0 it equals BP+OSD-0 on the same BP on every shot
tried (stage 1 is OSD's elimination, stopped where the syndrome is explained), and at the paper's
kappa 0.05 it is more accurate than BP+OSD-CS(7) on [[72,12,6]] and the gross code at p = 0.3% and
0.6%, 8 to 100 times faster (on the gross code at 0.3%, 20,000 shots: AC 26 failures in 5.9 ms a
shot, BP+OSD-CS(7) 32 in 61 ms; the paper's 310 µs a round at kappa 0 is our 370). The paper's
Table 1 at kappa 0 is about twice our kappa-0 error; its BP+OSD comparison data came from Bravyi
et al.'s circuits, which differ from ours (our BP+OSD-CS(7) on the gross code is half theirs).

Still to do: task 4's Collision Clustering and Local Clustering decoders, task 6's
composite and subgraph decoders as built-ins (qLDPC's are in `stabilizer_qec.qldpc`), task 7
and task 8.

## Tasks 2 and 3 in detail

Both references are Rust crates (MIT) with thin Python bindings, and their Python APIs reach
into the algorithms (MWPF's dual nodes, `grow`, invalid subgraphs and matrices; Fusion
Blossom's partitions, intermediate and perfect matchings), so each is ported as its algorithm,
in this crate's Rust without its dependencies, under its Python API.

**Task 2, MWPF 0.2.12** (`src/mwpf/`, `python/stabilizer_qec/mwpf/`):
- its default build, f64 weights (`OrderedFloat`, with its tolerance), not BigRational;
- model and decoding hypergraphs, the priority-queue dual module, the serial primal module and
  its plugins (union-find, single hair, joint single hair), the matrix module (basic, echelon,
  tight, tail, hair, complete), relaxers, the relaxer forest and the optimizer;
- the optimizer's LP by HiGHS 1.8.0 itself (vendored, see Status), as in MWPF's wheels;
- MWPF is deterministic, so the check is equality: subgraphs, bounds and snapshots;
- its Python files whole (`sinter_decoders`, `heralded_dem`, `ref_circuit`), its BP pre-decoder
  on this package's BP, its example codes, `Visualizer` writing its JSON snapshots, and its
  Python tests.

**Task 3, Fusion Blossom 0.2.13** (`src/fusion/`, `python/stabilizer_qec/fusion_blossom/`):
- the serial dual and primal modules (exact MWPM with virtual vertices, erasures and dynamic
  weights), and the parallel ones: partitions (`PartitionConfig`, `PartitionInfo`), units
  solved on threads and fused along their boundaries;
- its example codes with its random number generator, so their sampled errors are its;
- the check: matching weights equal to fusion_blossom's and to this package's blossom on every
  example code and on circuit models, serial and partitioned, and its Python tests.
