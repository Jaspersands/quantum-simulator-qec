# 1.8 "More decoders": BP+LSD, Relay-BP, colour-code matching, a search decoder

Part of the approved 1.6 → 1.9 roadmap (2026-10-06).

## Why

BP+OSD is the package's only decoder for codes whose faults set off three or more detectors, and
it is slow (1.5–2 ms a shot on the gross code). The field has moved on: localized statistics
decoding (BP+LSD), Relay-BP for real-time qLDPC decoding, Chromobius's matching for colour
codes, and Tesseract's search for the most likely error on any model. Each is a reference point
users compare against; having them here, checked like the others, completes the decoder set.

## Scope

1. **BP+LSD** (Hillmann, Berent, Quintavalle, Eisert, Wille, Roffe, 2024): after BP, grow
   clusters around the syndrome by BP's soft output and solve each cluster's OSD-like system
   locally, merging clusters as they grow. `BpLsd(model, *, max_iter, bp_method,
   ms_scaling_factor, lsd_order, lsd_method)` and `BpLsdDecoder(pcm, ...)`, matching `ldpc`'s
   `BpLsdDecoder` names. Oracle: `ldpc` 2.x's implementation, corrections equal shot for shot
   (ties documented as with BP+OSD); speed against it on the benchmarks page.
2. **Relay-BP** (Müller et al., IBM, 2025): chained memory-BP legs with disordered memory
   strengths, stopping at the first leg whose solution satisfies the syndrome, keeping the
   lowest-weight of several solutions. `RelayBp(model, *, legs, solutions, gamma0, gamma_range,
   iterations)`. No public reference implementation to match bit for bit: verified by
   reproducing the paper's gross-code curve shape and by the properties (every output explains
   the syndrome or reports failure).
3. **Colour-code matching** (Chromobius; Gidney and Jones, 2023): lift the colour-code model to a
   matching problem by the Möbius construction (each detector annotated with basis and colour in
   its 4th coordinate, Chromobius's convention), match with the existing sparse blossom, and
   project back. `ColorMatching(model)`. The colour-code generators (`Circuit.generated`
   colour code via an `annotate_colors=True` option producing Chromobius's coordinates, and
   `CssCode.color_code` memories) gain the annotation. Oracle: the `chromobius` package where
   installed, predictions equal shot for shot on its own circuits; logical error rates equal on
   ours.
4. **Search decoder** (Tesseract; Beni, Higgott and Shutty, Google, 2025): A* over sets of faults
   ordered by likelihood, with Tesseract's admissible heuristic and pruning options (beam,
   detector-order prioritisation), for any detector error model. `SearchDecoder(model, *,
   beam=..., ...)`. Oracle: the `tesseract-decoder` package where installed; otherwise exactness
   against brute force on small models (it finds the most likely error).
5. **sinter and docs.** All four as sinter kinds; tutorial 04 compares every decoder on the
   colour code and the gross code (logical error rate against time per shot); benchmarks rows
   against `ldpc` (LSD), `chromobius`, `tesseract-decoder` where installable in CI.

## Verification

Reference-package equality where a reference exists (ldpc, chromobius, tesseract), brute-force
optimality on small models for the search decoder, syndrome-consistency properties for all,
Hypothesis fuzzing of the new decoders' inputs (no panics on any model).

## Release

1.8.0, API additions only.
