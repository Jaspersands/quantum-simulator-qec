# 2.0: everything the other tools have, and one thing none of them has

Date: 2026-10-09. Branch `feature/2.0`. Inventory:
`docs/superpowers/notes/2026-10-09-parity-inventory.md` (IDs S*, P*, N*, L*, R*, D*, Q*, T*,
C*, M*, U*, F*, X*).

## Goal

Jasper's rule, after 1.9: "if a feature is in somewhere else, we also have that … we just
need everything they have and more." 2.0 closes every gap in the inventory, which comes from
25 packages and their documentation, and adds one capability none of them has.

## Global constraints

- Python package `stabilizer-qec` 2.0.0; Rust crate `stabilizer_qec` 2.0.0.
- 2.0 may break the 1.x API, but only where the reference tool's name or behaviour
  differs from ours. Each 1.x name that changes keeps a deprecated alias for all of 2.x.
- **Each parity feature is checked against its reference implementation** wherever that
  implementation can be run:
  - the reference is installed in a scratch venv from PyPI;
  - each feature gets a test that compares outputs on randomised inputs, skipped when the
    reference isn't installed;
  - matching is bit-for-bit where the reference is deterministic, and statistical (within
    error bars) where it samples.
  - Where no reference can be run (cloud-only or closed decoders, Julia), the check is the
    paper's own published numbers, or an exact oracle (the state vector, exhaustive
    enumeration, the ILP).
- Every feature is reachable from Python and from the Rust API (`src/api/`). The site gets
  what is visual or interactive.
- The fingerprints, benchmarks, fuzzing and Stim byte-identity tests from 1.x stay green.
- One commit per inventory group; CI is checked after every push. The release follows
  `release-procedure` memory.
- The repo style is long lines, and nothing is run through `cargo fmt`.
- No network calls at import or by default. Q18 (qecdb, the QLDPC challenge) is an opt-in
  function that fetches when called, and fails clearly offline.

## Workstreams, in build order

Each workstream is one plan (`docs/superpowers/plans/2026-10-09-2.0-W<n>-*.md`), built and
committed on `feature/2.0`. Later workstreams use earlier ones; for example, the encoders in
W7 use W2's `Tableau`.

### W1. Correct 1.9's claim (Tsim)

The README, site section 16, report, paper, CHANGELOG and the 1.9.0 GitHub Release notes
said no tool samples coherent errors beyond state-vector size. That is wrong.

- Tsim (QuEra, arXiv 2604.01059) samples Clifford+T and rotation circuits at 80+ qubits.
- Its cost grows exponentially with the number of non-Clifford gates.
- What holds: coherent noise on every gate (thousands of small rotations) is sampled only by
  ours.
- Name Tsim, add it to `paper.bib`, and edit the release notes.

### W2. Stim object model and the full Stim surface (S1–S62)

**Engine.** `src/stim_objects/`:
- `PauliString`, `Tableau` and `TableauSimulator` are built on the existing tableau engine.
- `CliffordString` and `FlipSimulator` sit on the frame sampler.
- `Flow` is solved over GF(2) on the circuit's stabilizer flows.
- `GateData` comes from `src/gates.rs`'s tables.
- Instruction, target and DEM-instruction objects are views onto `Circuit` and `DetectorErrorModel`.

**Circuit and DEM methods.**
- `to_qasm` (versions 2 and 3), `to_quirk_url` and `to_crumble_url`, as Stim writes them.
- `detecting_regions`.
- The SAT-problem exports (WCNF), identical to Stim's text.

**Samplers.** `sample_bit_packed`, `sample_write`, `convert_file` and Stim's class names.

**Diagrams.**
- `-html` wrappers of every type.
- `timeline-3d` and `matchgraph-3d` as glTF, which is Stim's format.
- `interactive`, which embeds the W12 editor.

**CLI.** `repl`, and `help gates/formats/<gate>/<format>`.

**Check.** Against Stim 1.16, for every method:
- randomised circuits from the fuzzer;
- objects compared through their text form, their numpy arrays and their unitaries.

### W3. PyMatching graph API (P1–P11)

- A `Matching` built by hand (edges, boundary, fault ids, merge strategies), from check
  matrices with repetitions and timelike weights, and from and to networkx/rustworkx.
- Graph queries.
- `decode(return_weight)`, `decode_to_edges_array` and the matched-detector outputs.
- `add_noise` and `draw`.
- The `pymatching predict` and `pymatching count_mistakes` CLI.

**Check.** Against PyMatching 2.4:
- identical predictions and weights on random graphs and on DEMs;
- identical edge arrays wherever PyMatching's own matching is unique.

### W4. Experiment tooling: sinter, deltakit and qec-util analysis (N1–N9, D9–D12, D15, U3–U6, U12)

**Collection.** `stabilizer_qec.sinter` becomes a full sinter:
- `Task`/`TaskStats`/`collect`/`iter_collect` with worker processes, resume, post-selection,
  custom error keys, CSV I/O, fits and plots;
- the CLI `collect/combine/plot`.

**Analysis.** A `stabilizer_qec.analysis` module provides:
- p_ij correlation matrices (exact and approximate) and DEM estimation from p_ij (D9);
- Λ and logical-error-per-round fits, including asymmetric ones, and quops prediction (D10);
- error budgets, i.e. the gradient of Λ in each noise parameter (D11);
- defect rates and diagrams (D12);
- threshold fits with finite-size scaling (U5);
- circuit utilities (U3) and DEM utilities (U4).

**Subset sampling** (U12): importance sampling by fault count, with the two bounds.

**Check.**
- Against sinter 1.16: the same CSV text for the same stats, the same fits and
  `predict_*` outputs.
- Against qec-util's formulas: p_ij on sampled data whose correlations are known.
- Against the qsample paper's teleportation example.

### W6. New decoders (D1–D4, U8, U10, U11, C1–C3, C5, Q14, M6, M7, X4, X5)

**From papers:**
- Collision Clustering (arXiv 2309.05558);
- the Local Clustering Decoder, adaptive and leakage-aware (arXiv 2411.10343);
- Ambiguity Clustering (arXiv 2406.14527);
- MWPF hypergraph matching and hypergraph union-find (MWPF; Wu et al.);
- parallel MWPM by partitions (Fusion Blossom);
- tensor-network maximum-likelihood decoding:
  - exact contraction (CUDA-Q's TN decoder);
  - MPS with a bond-dimension cut (qecsim's planar, toric and colour decoders).

**Exact or small decoders:** single- and multi-error lookup tables (plain, weighted,
observable), ILP, GUF, and a MaxSAT colour-code decoder.

**Wrappers:** analog (soft-syndrome) decoding, a sliding window around any inner decoder,
composite and subgraph decoders.

**Post-selection and checks:**
- post-selection by soft output (arXiv 2601.17757);
- leakage-aware decoding from heralds (D4);
- decoder conformance checks (X5), which run over every decoder we ship.

**The AI pre-decoder (C5).** A 3D CNN pre-decoder in the shape of NVIDIA's (arXiv
2604.12841), trained by our own trainer on our own samples, in front of matching:
- inference in Rust;
- training in Python with numpy only, or in Rust;
- the weights we ship are our own.

**Checks.**
- Against MWPF and fusion-blossom: identical weights.
- Against qecsim: MPS decodes on planar codes match.
- TN-ML against exhaustive maximum likelihood on small codes.
- LCD, AC and CC against their papers' published thresholds and curves.
- Lookup and ILP against brute force.
- The pre-decoder by the logical error it saves over matching alone.

**General codes:**

**Circuits and experiments:**

### W9. Clifford+T at scale, and the 2.0 headline (T1–T8)

**Parity (Tsim).**
- A stabilizer-rank sampler for circuits with few non-Clifford gates, at any qubit count:
  - T and T_DAG are decomposed by the standard magic-state stabilizer decomposition;
  - rotations, U3, R_PAULI, TPP, R_XX/YY/ZZ, CCZ and CCX are taken as plain gates;
  - exact probabilities; `to_matrix`, `tcount` and `is_clifford`.
- Check: against our state vector up to 24 qubits, bit-exact distributions. Against Tsim
  (installed) on its own examples, distributions agree within error bars.

**New: Clifford+T circuits with coherent noise on every gate.**
- Tsim's cost is exponential in the number of non-Clifford gates, so coherent noise on every
  gate is out of its reach. Our 1.9 coherent sampler needs a Clifford reference circuit.
- 2.0 joins the two:
  - the few logical non-Clifford gates (cultivation's T checks, a distillation round,
    injection) go to the stabilizer-rank sampler;
  - the thousands of small coherent rotations go to the coherent kernel's importance weights;
  - the weight of a shot is computed per stabilizer-rank term.
- First target: magic-state injection and a d = 3 cultivation-style T check under
  over-rotation on every gate. These are full-size circuits that neither tool can sample
  today.
- Check:
  - exact against the state vector on every branch of small random Clifford+T circuits with
    coherent noise (the 1.9 `exact.rs` harness, extended);
  - within error bars against the state vector at ≤ 24 qubits.
- The result: how much the twirl misjudges a magic state's fidelity under coherent noise.

## Out of scope, and why

Nothing in the inventory is dropped. Two items have limits:

- **Q18** fetches from third-party sites (qecdb, the QLDPC challenge) and GAP/Magma. These
  run only when called; groups are computed natively.
- **C7.** The CUDA-Q realtime pipeline to NVQLink hardware has no equivalent here. Our
  server covers the API and the latency stats, not the hardware link.

## Risks

**Scale.** About 300 inventory lines. Order matters: W2's objects underlie W7, W9 and W10.

**Arithmetic matches.**
- The fixed-point Relay-BP's integer behaviour.
- PyMatching's tie-breaking in `decode_to_edges_array`.
- Each reference's sampling RNG: sampled outputs are compared statistically, not bit for bit.

**The headline (W9) is research.**
- The per-term coherent weight must be proven exact on the extended harness before any
  number is published.
- If the joint sampler's variance is too high at d = 3, the release says so, with the
  measured effective sample size, as 1.9 did.
