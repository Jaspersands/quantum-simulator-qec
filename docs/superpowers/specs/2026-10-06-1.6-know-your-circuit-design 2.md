# 1.6 "Know your circuit": distance, error explanation, a CLI, Stim's timeline; and a JOSS paper

Approved roadmap (2026-10-06): 1.6 → 1.7 → 1.8 → 1.9, each archived on Zenodo by its GitHub
Release. Standing rules: do-both/biggest on open questions, Stim/PyMatching/ldpc parity checked
by tests, no `cargo fmt`, one GitHub Release per version.

## Why

1.5 added codes whose circuits nobody hand-checked: the generic `CssCode` memory, the 90/108/288
bivariate bicycle codes, codes from arbitrary polynomials. Their *circuit* distance is unknown;
the docs can only quote the code's. Stim answers this with `shortest_graphlike_error` and
`search_for_undetectable_logical_errors`, and answers "where did this fault come from" with
`explain_detector_error_model_errors`. These are the three analysis tools researchers reach for
after sampling, and the package lacks all three. The command line is the other half of Stim's
surface it lacks. And 1.5's timeline text is "after Stim's" rather than Stim's.

## Scope

### A. Error explanation (`src/explain.rs`)

- The error-model builder already walks every fault; give it a mode that records, per emitted
  fault class, the circuit locations that produced it: instruction index path (through
  `REPEAT` blocks: iteration and instruction per level, Stim's `stack_frames`), target range,
  tick offset, the flipped Pauli product (with qubit coordinates), the flipped measurement
  (record index, observable), and the noise tag.
- `Circuit.explain_detector_error_model_errors(*, dem_filter=None,
  reduce_to_one_representative_error=False)` → `list[ExplainedError]`, with
  `ExplainedError.dem_error_terms` and `.circuit_error_locations` (`CircuitErrorLocation`:
  `tick_offset`, `flipped_pauli_product`, `flipped_measurement`, `instruction_targets`,
  `stack_frames`, `noise_tag`), names and `str()` text equal to Stim's.
- The representative error is Stim's choice (the first location, in Stim's order); loops are
  walked unrolled for this mode (as Stim does), with the existing unroll limit.

### B. Circuit distance (`src/distance.rs`)

- `DetectorErrorModel.shortest_graphlike_error(ignore_ungraphlike_errors=True)` → a
  `DetectorErrorModel` of the faults, Stim's algorithm: breadth-first search over (detector,
  observable mask) states on the graph-like edges, boundary as a node; result length equal to
  Stim's on every test case (the set may differ only among equal-length ties).
- `Circuit.shortest_graphlike_error(*, ignore_ungraphlike_errors=True,
  canonicalize_circuit_errors=False)` → explained errors (via A).
- `Circuit.search_for_undetectable_logical_errors(*, dont_explore_detection_event_sets_with_size_above,
  dont_explore_edges_with_degree_above, dont_explore_edges_increasing_symptom_degree,
  canonicalize_circuit_errors=False)`: Stim's heuristic search over symptom sets for
  hyperedge errors, same parameters, same guarantees (finds a logical error of the length Stim
  finds on every test case).
- Exact distance for small codes beyond Stim: `DetectorErrorModel.distance(method="milp")`
  using the integer program already used for the gross code's gauging distance (HiGHS via
  scipy where installed); documented as exponential-worst-case, for small models.
- Use: tests state the circuit distance of every built-in memory: rotated/unrotated surface,
  colour code, bivariate bicycle 72/90/108/144 (graph-like search where it applies, heuristic
  search otherwise), and `CssCode` hypergraph products. Findings go in the README and docs,
  including any circuit whose distance is below its code's (an honest finding, not a bug, for
  the generic X-then-Z schedule).

### C. The command line (`stabilizer-qec`, Python entry point)

- Subcommands with Stim's names and flags: `sample`, `detect`, `m2d`, `analyze_errors`,
  `explain_errors`, `diagram`, `gen`, `convert`, `sample_dem`, `help`; reading stdin / `--in`,
  writing stdout / `--out`, `--seed`, `--shots`, `--out_format`, `--obs_out` etc.
- Result formats: Stim's `01`, `b8`, `r8`, `ptb64`, `hits`, `dets` (adding r8, ptb64, hits, dets
  to the engine's shots module), both directions, as Stim defines them.
- `sample_dem`: sampling directly from a detector error model (new sampler path).
- Plus a `decode` subcommand after PyMatching's CLI (`--decoder matching|union_find|bposd|...`).
- Tests: every subcommand against `stim <command>` on the same inputs; outputs byte-identical
  where Stim's are deterministic (analyze_errors, m2d, convert, gen, diagram, explain_errors),
  statistically equal where sampled.

### D. Diagrams identical to Stim's

- `timeline-text` character for character (Stim's layout: loop boundaries as `|` columns,
  symbolic `rec[2+iter*2]` lookbacks, accumulated `SHIFT_COORDS`, its bracket rules).
- `timeslice-svg` (the qubits at their coordinates, one panel per tick, gates drawn on them) and
  `detslice-with-ops-svg`; `tick` accepting a `range`, and `rows`, as Stim does.
- Test: the text diagram equal to Stim's for every generated circuit and the random circuits of
  `tests/test_stim_gates.py`; SVGs well-formed and visually checked.

### E. JOSS paper (`paper/paper.md`, `paper/paper.bib`)

- Journal of Open Source Software format: summary, statement of need (verified QEC tooling in
  one package: Stim-identical models, PyMatching-speed matching, BP+OSD, qLDPC codes, real
  hardware data, browser engine), comparison with Stim/PyMatching/ldpc/sinter/Chromobius/Tesseract,
  verification approach, acknowledgements, references.
- `paper/` checked by CI with JOSS's `openjournals/inara` draft action building the PDF.
- Submission is the author's to make (it needs their JOSS account); the spec delivers the
  ready paper and a checklist. The Zenodo DOI of 1.6 goes into `CITATION.cff` and a README badge after release.

## Out of scope

Stim's `shortest_error_sat_problem` / `likeliest_error_sat_problem` (WDIMACS export) is cheap and
in scope only as stretch; `timeline-3d`, `interactive` diagrams and the REPL are out.

## Verification

Every new public function has Stim's behaviour as its test oracle where Stim has the function;
the CLI is tested end to end against the `stim` executable; distance results are cross-checked
between graph-like search, heuristic search and MILP on small models. Benchmarks page gains a
row for `shortest_graphlike_error` against Stim's.
