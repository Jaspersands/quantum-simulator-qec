# 1.7 "Faster than the references"

Part of the approved 1.6 → 1.9 roadmap (2026-10-06).

## Why

The benchmarks recorded with 1.5.0 (`data/bench/runs.json`) show where the package is slower:

| | Apple silicon | Linux x86_64 (CI) |
|---|---|---|
| error model, d = 11 | 2.3× Stim | 0.82× |
| sampling | 0.82× | 0.74× |
| m2d | 1.16× | 0.71× |
| matching | 1.10× PyMatching | 1.40× |
| correlated matching | 1.12× | 1.33× |

The aim of 1.7 is every ratio at or below 1.0 on both kinds of machine, with results unchanged:
models identical text, samples identical for a seed, decodes bit-identical (matcher fingerprints,
`tools/matcher_bench.py --check`).

## Scope

1. **Measurement first.** `tools/bench.py` gains `--profile` (per-benchmark perf/samply
   flamegraph capture where available) and a `workflow_dispatch` CI job that runs the suite on
   Linux x86_64 *and* Linux arm64 runners and prints ratios, so Linux numbers come from Linux,
   not Rosetta. Every optimisation lands with before/after ratios from both.
2. **Matching on x86_64.** Find why the matcher is 1.4× on x86 but 1.1× on ARM (candidates:
   branch layout of `next_node_event`, the radix heap's word scans, memory layout of the flooder,
   target-cpu: PyMatching wheels are built for x86-64-v2/v3). Options in order: algorithmic and
   layout fixes; `#[cfg(target_feature)]` paths; building wheels with `x86-64-v2` (SSE4.2/POPCNT,
   universal since 2009) if the gain is real, documented in the README.
3. **Error models on ARM.** Profile the backward walk on aarch64 (sparse XOR of sensitivity sets,
   BTreeMap class merging, the `MERGED` accounting); replace hot sorted-vector merges and map
   lookups with flat hash maps or arena-backed sets where profiles point.
4. **Wider sampling.** The frame sampler processes 64 shots per word; go to 256-shot blocks
   (`[u64; 4]` lanes the compiler vectorises on AVX2/NEON), keeping the per-batch seeding so a seed
   gives the same shots on any machine and thread count (shots map to the same RNG streams).
5. **m2d on ARM.** Same treatment as sampling (it shares the frame path).
6. **Threads.** Benchmarks at 1, 4 and all cores for sampling and decoding, on the page.

## Verification

Bit-identity gates before any merge: the matcher fingerprints, the Stim-text tests, the sampler's
seed-stability tests (`tests/test_threads.py`, same shots for a seed across thread counts and,
new, across block widths), full suites. Benchmarks recorded for both machine kinds with the
release; CI's regression check keeps them.

## Release

1.7.0, internal changes only (no API change expected); README and report speed tables
regenerated (`tools/readme_tables.py`).
