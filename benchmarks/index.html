How fast, against Stim and PyMatching

The same jobs on the same machine, one thread each, recorded at every release and checked on every push

Method

Each benchmark times one job in this package and the same job in the reference: Stim for error models, the graph-like distance, sampling and measurement conversion, PyMatching for matching. Each time is the fastest of several runs after a warm-up (five by default), on one thread. The ratio is this package's time over the reference's, so below 1 is faster. Times depend on the machine; ratios carry from machine to machine far better, so they are what is recorded and compared.

Stim's sampler and PyMatching's batch decoding run on one thread. This package's run on as many as it is given, giving the same shots and decisions on any number: the rows marked "4 threads" and "every core" (the core count is in each run's heading) have no reference and show how its time per shot scales.

Every push runs the benchmarks in continuous integration and fails if any ratio is more than twice the one last recorded on the same kind of machine. The table appears in the run's summary. Recorded runs are kept in data/bench/runs.json; to reproduce one, install the package with Stim and PyMatching and run python tools/bench.py.
